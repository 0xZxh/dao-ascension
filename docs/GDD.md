## 1. 项目概述

### 1.1 立项初衷

1. 【确定】品类定位：轻度仙侠养成 + 回合制爬塔，H5 网页端，单局操作以“点击建筑 → 即时结算”为主，不含实时操作战斗。
2. 【确定】要解决的问题：
   - 链游高频操作需逐笔钱包签名，打断节奏。本项目以“会话密钥代签”为目标方案，玩家在游戏内全程不弹钱包窗（当前 Demo 实现程度见 R-15）。
   - 修仙养成普遍为单一战力数值。本项目把生存（气血）和输出（攻击）拆给两个独立的生产系统，再用爬塔检验两者的配比。
3. 【确定】参赛方向：NEAR 黑客松 games / nfts 赛道为主，agents / defi 为辅（国库结算接入 NEAR Intents 1Click 报价）。

### 1.2 核心体验

| 编号 | 体验点 | 规则支撑 |
| :--- | :--- | :--- |
| E1 | 种田决定能扛多久 | 气血上限只能由灵圃炼丹永久提升（境界升级也加，但幅度小，见 4.3）；战斗回血丹只来自灵圃 |
| E2 | 打铁决定打得多快 | 攻击力主要来源为佩戴法宝；法宝只能由剑庐锻造 |
| E3 | 爬塔给材料，材料回流种田和打铁 | 锻造用的玄铁/陨铁、高阶灵种主要靠秘境通关掉落 |
| E4 | 三条路线都能上榜 | 战斗、种植、锻造各有独立周榜，非战斗型玩家可只走种植或锻造路线 |
| E5 | 角色即资产 | 角色绑定独立子账户，可整号转让（当前为模拟，见 R-15） |

### 1.3 差异化卖点

| 维度 | 同类常见做法 | 本项目做法 | 状态 |
| :--- | :--- | :--- | :--- |
| 签名交互 | 每次链上操作弹钱包 | 会话密钥代签，限定可调用方法与 Gas 额度 | 【确定】交互形态；链上落地【待讨论】R-15 |
| 属性来源 | 等级统一加全属性 | 气血←种植、攻击←锻造、材料←爬塔，三者互锁 | 【确定】 |
| 资产形态 | 角色、装备、土地拆成多个 NFT | 角色 NFT 绑定子账户，背包、灵田、修为随账户整体转移 | 【确定】规则；链上落地【待讨论】 |
| 奖励来源 | 增发代币 | 玩家消耗汇入国库，按固定比例回流周榜 | 【确定】分账规则；产出端存在系统发放，见 7.4、R-09 |

### 1.4 预期时长

| 指标 | 目标值 | 状态 | 依据 |
| :--- | :--- | :--- | :--- |
| 新手引导（创角 → 解锁 4 座建筑） | 3 ~ 5 分钟 | 【确定】 | 引导共 5 步，每步 1 ~ 3 次点击，战斗动画每回合 0.65 秒 |
| Demo 完整内容（通关第 5 层） | 25 ~ 40 分钟 | 【待确认】 | 需 QA 实测，见 6.3 难度曲线 |

## 2. 核心循环

### 2.1 主循环（文字流程）

```
[创角] 选择道身 → 获得初始资源（260 灵石、玄铁 6、陨铁 2、1阶种子 2、2阶种子 1、回春丹 2）
   │
   ▼
[灵圃] 播种（扣种子；无种子则扣灵石→国库）
   → 灵泉浇灌（作物立即成熟，药力 ×1.25）
   → 采摘炼丹（永久 +最大气血；+回春丹；+百草榜积分）
   │
   ▼
[剑庐] 锻造（扣玄铁、陨铁、灵石→国库）
   → 生成法宝（品阶、攻击、防御、暴击、锻造积分）
   → 若新法宝攻击 ≥ 当前佩戴，自动佩戴（+攻击；+神工榜积分）
   │
   ▼
[秘境] 支付门票（灵石→国库）→ 自动回合制战斗（低血自动服丹）
   ├─ 胜：灵石、修为、玄铁、陨铁、1颗灵种、诛魔榜积分 → 回到 [灵圃] / [剑庐]
   └─ 败：门票与已服丹药不返还，无奖励 → 回到 [灵圃] 堆气血 或 [剑庐] 换更高阶法宝
   │
   ▼
[天榜] 结算：国库余额 50% 按三榜名次发放，20% 划入开发运营金库，30% 留存滚入下期
```

循环的关键约束（【确定】）：

1. 灵圃不产出攻击，剑庐不产出气血。任何单一系统都不能独立通关第 2 层及以上（6.3 的模拟数据给出依据）。
2. 剑庐的材料来源是秘境，秘境的通关条件是气血与攻击。新手阶段由初始资源（玄铁 6、陨铁 2）启动第一次锻造。
3. 所有灵石消耗（买种、锻造费、门票）100% 进入国库，不直接销毁。

### 2.2 短期 / 中期 / 长期目标

| 层级 | 时间尺度 | 玩家目标 | 系统给出的里程碑 | 状态 |
| :--- | :--- | :--- | :--- | :--- |
| 短期 | 单次会话（≤15 分钟） | 完成引导；收一轮灵田；打出第一把剑；过第 1 层 | 引导步骤推进、建筑逐个解锁、首胜突破筑基期 | 【确定】 |
| 中期 | 1 ~ 3 天 | 打出二阶、三阶法宝；用三阶种子堆气血；通关第 5 层 | `highestFloorCleared = 5`；三榜任一进入前 2 | 【确定】内容；时长【待确认】 |
| 长期 | 赛季（4 周） | 周榜排名、角色整号增值后转让 | 每周结算、赛季重置、角色交易 | 【待讨论】（第 6 层以上内容、赛季规则、交易市场均未实现） |

## 3. 世界观与剧情

> 本章只定义玩法需要的设定，不含美术形象描述。

### 3.1 背景

【确定】上古魔劫后灵脉断裂，修士只能在各自洞府内自给自足：内以灵草炼丹固本，外以法宝斩妖取材。宗门以“天榜”按功绩分配宗门公库的灵石。此设定对应三个玩法：灵圃（炼丹固本）、剑庐（炼器斩妖）、天榜（公库分配）。

### 3.2 势力

| 势力 | 玩法职能 | 出场位置 | 状态 |
| :--- | :--- | :--- | :--- |
| 太虚仙门 | 玩家所属宗门；提供四座建筑与引导 NPC | 全局 | 【确定】 |
| 玄机长老（NPC） | 引导任务发布者；每次操作后刷新一句反馈文案 | 引导横幅、`elderCounsel` 字段 | 【确定】 |
| 秘境妖魔 | 爬塔敌人，5 层各 1 个单位 | 秘境 | 【确定】 |
| 竞争道友（NPC） | 周榜上的 3 名固定对手，积分为常量 | 天榜 | 【确定】Demo 用；Alpha 由真实玩家替代【待讨论】 |

### 3.3 主角设定

【确定】玩家为太虚仙门新入内门弟子。创角时选择 5 种道身之一，道身只决定初始属性与初始物资，不决定可用系统（所有道身都能种植、锻造、爬塔）。属性见 4.2。

### 3.4 主线梗概

【确定】主线即新手引导，共 6 个阶段（`tutorialStage` 0 ~ 6），严格顺序推进，不可跳步（调试按钮除外，见 R-14）：

| 阶段 | 任务文案要点 | 完成条件（客户端判定） | 完成后效果 |
| :--- | :--- | :--- | :--- |
| 0 | 创建道身 | 提交 `CREATE_CHARACTER` | 进入洞府，阶段 → 1 |
| 1 | 播下第一株灵草 | 对任意空地块成功播种 | 阶段 → 2 |
| 2 | 灵泉浇灌 | 对生长中地块浇灌 | 阶段 → 3 |
| 3 | 采摘炼丹 | 对成熟地块采摘 | 解锁剑庐，阶段 → 4 |
| 4 | 铸造本命法宝 | 锻造成功一次 | 解锁秘境，阶段 → 5 |
| 5 | 通关秘境 | 任意层战斗胜利 | 解锁天榜，阶段 → 6 |
| 6 | 自由游玩 | — | 引导横幅显示常驻提示 |

边界说明：

- 【确定】阶段 1 → 2 的判定为“任意地块播种”，不限定 1 号地块（引导文案写 1 号地块，仅为指引）。
- 【确定】阶段 5 → 6 的判定为“任意层胜利”。实际上只有第 1 层可在此阶段打过（见 6.3）。
- 【确定】战斗失败不推进阶段，不扣阶段进度。
- 引导进度只存在于浏览器内存，刷新页面会回到创角界面（R-05）。

### 3.5 支线规则

【待讨论】Demo 无支线。Alpha 拟采用“计数器触发型”支线，规则模板如下，触发条件与奖励需数值评审：

| 支线 ID | 触发计数器 | 阈值 | 奖励 | 是否可重复 |
| :--- | :--- | :--- | :--- | :--- |
| SQ-01 | 累计采摘 3 阶作物次数 | 【待确认】 | 【待确认】 | 否 |
| SQ-02 | 连续锻造未出最高品阶次数 | 【待确认】 | 下次锻造品阶保底 | 是（触发后清零） |
| SQ-03 | 同一层累计失败次数 | 【待确认】 | 一次性回春丹补给 | 每层一次 |

## 4. 角色 / 单位设计

### 4.1 角色属性字段

【确定】数据结构 `CultivatorNftAccount`：

| 字段 | 含义 | 计算规则 |
| :--- | :--- | :--- |
| `realm` / `realmLevel` | 境界 / 层数 | 练气期 → 筑基期 → 结丹期 → 元婴期，每境 1 ~ 3 层 |
| `exp` / `maxExp` | 修为 / 升级所需 | 仅秘境胜利获得修为 |
| `baseHp` | 基础气血 | 道身初始值 + 境界成长 |
| `herbBonusHp` | 灵丹永久气血 | 每次采摘累加，无上限 |
| `maxHp` | 最大气血 | `baseHp + herbBonusHp` |
| `baseAtk` | 基础攻击 | 道身初始值 + 境界成长 |
| `weaponBonusAtk` | 法宝攻击 | 等于当前佩戴法宝的 `atkBonus`；未佩戴为 0；背包内未佩戴法宝不计 |
| `atk` | 面板攻击 | `baseAtk + weaponBonusAtk` |
| `def` | 防御 | 道身初始值 + 境界成长；**不含法宝防御**（法宝防御只在战斗中叠加，R-07） |
| `critRatePct` | 暴击率 | 未佩戴：道身初始值；佩戴后：`10 + 法宝暴击`（R-01） |
| `hp` | 当前气血 | 每场战斗开始时重置为 `maxHp`，战斗外无消耗途径 |

### 4.2 道身初始配置（创角）

【确定】`CREATE_CHARACTER` 的 `avatarClass` 取值与服务端写入值。未列出的字段沿用默认值：防御 12、暴击 10%、回春丹 2、丹药回血量 110、境界练气期 3 层、修为 40/120。

| `avatarClass` | 道身 | baseHp | baseAtk | def | crit | 额外物资 | 解锁 |
| :--- | :--- | ---: | ---: | ---: | ---: | :--- | :--- |
| `saintess` | 瑶池圣女 | 210 | 38 | 12 | 10% | 回春丹 4（替代默认 2） | 默认 |
| `sword` | 太虚剑修 | 170 | 48 | 12 | 18% | — | 默认 |
| `venerable` | 太古仙尊 | 240 | 40 | 22 | 10% | — | 默认 |
| `fox` | 青丘灵狐 | 200 | 44 | 12 | 17% | — | 默认 |
| `demon` | 九幽魔尊 | 185 | 54 | 12 | 22% | — | 默认；【待讨论】改为通关第 5 层解锁 |

边界：

- 【确定】`avatarClass` 传入非法值时，服务端按 `saintess` 处理。旧值 `alchemy` 映射为 `saintess`，`body` 映射为 `venerable`（向下兼容）。
- 【确定】道号为空时，服务端使用默认道号“云清浅”。前端限制最长 14 个字符，服务端未校验长度（R-16）。
- 【确定】重新创角会整体重置角色、国库、榜单为初始状态。
- 客户端创角预览卡显示的防御/暴击与上表不一致（R-02）。

### 4.3 境界成长

【确定】仅在秘境胜利结算后检查，规则如下：

1. 当 `exp ≥ maxExp` 时循环执行：`exp -= maxExp`，`realmLevel += 1`，`baseHp += 25`，`baseAtk += 8`，`def += 3`，`maxExp = round(maxExp × 1.35)`。
2. 若 `realmLevel > 3`：`realmLevel = 1`；若当前不是元婴期，则进入下一境界，并额外 `baseHp += 80`、`baseAtk += 24`、`def += 8`。
3. 元婴期 3 层之后继续升级：层数回到 1，境界保持元婴期，只享受第 1 条的小幅成长，不再获得第 2 条加成。
4. 一次结算可连升多级（溢出修为继续循环）。
5. 结算后 `maxHp`、`atk` 重新计算，`hp` 回满。暴击率不随境界变化。

成长参考（由规则推导，【确定】）：

| 节点 | 累计修为需求 | 境界加成合计（HP / ATK / DEF） |
| :--- | :--- | :--- |
| 创角 | 练气 3 层，40/120 | 0 / 0 / 0 |
| 第 1 层首胜（+90 修为） | 130 ≥ 120，突破筑基 1 层 | +105 / +32 / +11 |
| 筑基 2 层 | 下一级需 162 | +130 / +40 / +14 |

【待确认】新角色从练气 3 层起步，导致首胜即突破筑基（引导期获得较大属性跳变）。是否改为练气 1 层起步，需结合第 1 层难度重新评估。

### 4.4 技能

【确定】Demo 无主动技能。战斗中角色行为固定为：普攻 → 受击 → 条件触发服丹。
【待讨论】Alpha 技能方案（每道身 1 个被动），需数值评审：

| 道身 | 被动技能（草案） | 触发条件 | 效果参数 |
| :--- | :--- | :--- | :--- |
| 瑶池圣女 | 回春 | 服丹时 | 回复量 +【待确认】% |
| 太虚剑修 | 剑心 | 暴击时 | 暴击倍率 +【待确认】 |
| 太古仙尊 | 护体 | 受击时 | 额外减伤【待确认】点 |
| 青丘灵狐 | 灵巧 | 每 N 回合 | 闪避一次攻击 |
| 九幽魔尊 | 嗜血 | 气血 < 30% | 攻击 +【待确认】% |

### 4.5 敌方单位

【确定】敌方只有 `monsterHp`、`monsterAtk`、`monsterDef` 三个战斗属性，无暴击、无回血、无技能。具体数值见 6.2。
【待讨论】第 4、5 层增加被动机制（如狂暴、护盾），用于打破“纯堆数值”的线性体验。

## 5. 核心系统设计

### 5.1 灵圃（种植 / 炼丹）

**目标**：提供永久最大气血、战斗回血丹、百草榜积分。

**规则**（【确定】）：

1. 共 9 块地块，`plotId` 0 ~ 8，相互独立。
2. 地块状态机：`EMPTY` →（播种）→ `GROWING` →（浇灌）→ `READY` →（采摘）→ `EMPTY`。不存在其他转移路径。
3. 种子配置：

| 阶 | 作物 | 产出丹药 | 无种子时灵石价 | 基础 +HP | 基础丹数 | 单颗回血 | 基础榜分 |
| ---: | :--- | :--- | ---: | ---: | ---: | ---: | ---: |
| 1 | 聚灵青叶草 | 九转回春丹 | 15 | 40 | 2 | 95 | 35 |
| 2 | 九叶赤血芝 | 龙虎气血丹 | 35 | 95 | 3 | 165 | 85 |
| 3 | 千年玄黄朱果 | 太乙涅槃仙丹 | 75 | 210 | 4 | 290 | 190 |

4. 浇灌后结算值（因浇灌为必经步骤，实际每次采摘都按此表结算）：

| 阶 | 实际 +HP（×1.25 取整） | 实际丹数（+1） | 实际榜分（×1.25 取整） |
| ---: | ---: | ---: | ---: |
| 1 | 50 | 3 | 44 |
| 2 | 119 | 4 | 106 |
| 3 | 263 | 5 | 238 |

**交互流程**（【确定】）：玩家在顶部选择种子阶位后，点击地块，按地块当前状态执行对应操作（一个地块一次点击只执行一个操作）：

| 地块状态 | 点击执行 | 服务端校验 | 成功结果 |
| :--- | :--- | :--- | :--- |
| `EMPTY` | 播种 | 有该阶种子则扣 1 颗；否则校验灵石 ≥ 价格并扣灵石，灵石计入国库“买种”分项 | 状态 → `GROWING` |

**限制条件与边界**：

### 5.3 秘境（战斗）

**目标**：检验气血 × 攻击配比；产出灵石、修为、锻造材料、灵种；提供诛魔榜积分。

**规则**（【确定】）：

1. 入场：校验灵石 ≥ 门票，扣门票计入国库“门票”分项。门票在战斗开始前扣除，**无论胜负均不返还**。
2. 开战：角色 `hp` 重置为 `maxHp`。
3. 回合上限 12。每回合顺序固定：
   1. 角色攻击：
      ```
      基础伤害 = max(18, 角色攻击 − 妖兽防御)
      是否暴击 = (回合序号为奇数) 且 (角色暴击率 ≥ 15)
      实际伤害 = 暴击 ? round(基础伤害 × 1.55) : 基础伤害
      ```
      妖兽气血 ≤ 0 → 立即胜利，本回合后续步骤不执行。
   2. 妖兽攻击：
      ```
      伤害 = max(12, 妖兽攻击 − (角色防御 + 佩戴法宝防御))
      ```
   3. 自动服丹：若角色气血 > 0 且 < `maxHp × 0.55` 且回春丹 > 0 → 消耗 1 颗，回复 `min(maxHp − 当前气血, 丹药回血量)`。
   4. 角色气血 ≤ 0 → 失败。
4. 第 12 回合结束妖兽仍存活 → 判负。
5. 胜利结算：灵石、修为、玄铁、陨铁、指定阶种子 1 颗、诛魔榜积分；`highestFloorCleared = max(原值, 本层)`；执行境界检查（4.3）。
6. 失败结算：无任何奖励；已消耗回春丹不返还。

**交互流程**（【确定】）：玩家选择层数 → 点击挑战 → 服务端一次性算完整场战斗并返回日志 → 客户端按每条日志 0.65 秒逐条回放（攻击位移、受击、飘字、服丹光效）→ 回放完毕显示结算。回放期间禁用挑战按钮与层数切换。

**限制条件与边界**：

- 【确定】暴击当前为确定性规则：暴击率 < 15 的角色永不暴击，≥ 15 的角色每个奇数回合必暴击，暴击率数值大小本身不影响结果（R-03）。
- 【确定】每回合最多服 1 颗丹，单场服丹次数无上限。
- 【确定】妖兽一击将角色打到 0 时直接失败，不触发服丹。
- 【确定】服丹判定在妖兽攻击之后，角色攻击之前不判定。
- 【确定】层数可任意选择，**不要求按顺序通关**（未通关第 1 层也可直接挑战第 5 层）。【待讨论】是否改为需通关前一层。
- 【确定】已通关层数可无限重复挑战，奖励每次全额发放，无每日上限（R-10）。
- 【确定】战斗结果在服务端计算，客户端只做回放，不可篡改。

### 5.4 天榜与国库（结算）

**目标**：把玩家消耗按固定比例返还给三类玩家；保障项目运营资金。

**规则**（【确定】）：

1. 国库流入：买种灵石、锻造费、秘境门票，分别记入 `feeBreakdown` 三个分项；初始底池 680 灵石（其中 400 记为创世注入）。
2. 结算时以当前国库余额 `T` 为基数：

| 去向 | 比例 | 计算 | 字段 |
| :--- | ---: | :--- | :--- |
| 三榜奖池 | 50% | `round2(T × 0.5)` | `extractedRewardPoolStones` |
| 开发运营金库 | 20% | `round2(T × 0.2)` | `devOpsAllocatedStones`，累计入 `cumulativeDevOpsRevenueStones` |
| 留存滚存 | 30% | `T − 奖池 − 金库` | `treasuryReserveRemaining`，成为新的国库余额 |

3. 三榜奖池再分配：诛魔榜 40%、百草榜 30%、神工榜 30%。
4. 各榜按积分降序排名（玩家 + 3 名 NPC 共 4 人），名次权重：第 1 名 50%、第 2 名 25%、第 3 名 15%、第 4 名 10%。
5. 玩家获得三个榜单份额之和，计入玩家灵石；并按 1 灵石 = 0.1 美元换算，请求 NEAR Intents 1Click 跨链报价（默认目标 Solana USDC）。
6. 结算后期数 `currentEpoch + 1`，写入结算历史。

**限制条件与边界**：

- 【确定】积分相同时，排序沿用 JavaScript 稳定排序，玩家（列表首位）排在同分 NPC 之前。
- 【确定】NPC 分得的份额从国库扣除但不发放给任何账户（Demo 内直接消失，R-13）。
- 【确定】跨链报价金额设有 1.5 美元下限，玩家应得低于 1.5 美元时报价金额高于实际应得（R-13）。
- 【确定】**结算当前无周期限制，可随时重复点击**，每点一次都按当时国库余额重新分账（R-06，Demo 阶段最高优先级经济缺陷）。

### 7.4 通胀控制

**现状分析**（【确定】）：

- 秘境每次胜利净产出 = 奖励 − 门票 = +38 / +73 / +125 / +200 / +335 灵石，且无次数限制。这部分灵石由系统凭空发放，不来自国库。
- 国库只回收消耗，因此“零增发”只在国库分账环节成立，在全局层面不成立。
- 当灵石不可兑换外部资产时，这只影响游戏内节奏，可接受。
- 一旦灵石可按 0.1 美元兑出，秘境奖励即为项目方无上限的美元负债，模型不可持续（R-09）。

**控制手段**：

| 编号 | 手段 | 规则 | 状态 |
| :--- | :--- | :--- | :--- |
| C1 | 国库分账上限 | 每次结算只发放余额的 50%，30% 留存，国库余额不会被单次结算清零 | 【确定】 |
| C2 | 结算周期锁 | 每周仅结算一次，由服务端定时触发 | 【待讨论】（R-06） |
| C3 | 双货币拆分 | 秘境奖励改发“绑定灵石”（可消费、不可提现）；只有天榜结算发放“可提现灵石”，且总额 ≤ 国库实收 | 【待讨论】，建议 Alpha 必做 |
| C4 | 重复挑战递减 | 见 6.4 | 【待讨论】 |
| C5 | 锻造作为后期主消耗 | 真随机品阶 + 保底，使高阶玩家持续投入灵石追求更高品阶 | 【待讨论】（依赖 R-03 修复） |
| C6 | 赛季重置 | 每赛季清零榜单积分；属性与物资是否保留【待确认】 | 【待讨论】 |

### 7.5 开发运营金库测算模板

【确定】金库收入 = 每次结算时国库余额 × 20%。国库余额的增长完全来自玩家消耗，因此金库收入与活跃玩家消耗强相关。
以下为测算模板，参数需运营提供，本文不预填：

```
周国库流入 F = DAU × 人均日消耗灵石 × 7
稳态下国库余额 T ≈ F / (1 − 0.3)        （每期留存 30%）
周金库收入   = 0.2 × T × 0.1 美元/灵石
周榜单支出   = 0.5 × T × 0.1 美元/灵石
```

| 场景 | DAU | 人均日消耗灵石 | 周流入 F | 稳态 T | 周金库收入（美元） | 月运营成本（美元） | 覆盖率 |

| 保守 | | | | | | | |
| 基准 | | | | | | | |
| 乐观 | | | | | | | |

### 12.5 正式版客户端

Beta 之后做可安装的正式游戏。框架只在 Cocos 与 Unity 中选一个，选定前不并行维护两套客户端。网页版保留为可试玩的公开版本。玩法循环、数值表和国库规则以当时已冻结的版本为移植底稿，不在换引擎时重做一套规则。
